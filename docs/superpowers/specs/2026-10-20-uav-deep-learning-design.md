# 无人机开发深度学习路线设计（Agent × UAV 转型）

- 日期：2026-10-20
- 使用者：周健健（成都，硕士在读，2028 届）
- 依据：《无人机方向转型规划_两个月启动计划.docx》
- 定位：无人机软件 / 智能体应用岗，避开纯算法研究岗

## 1. 背景与现状

### 1.1 已有基础

- Python / Java 软件工程能力，具备 AI Agent（大模型智能体）开发经验
- 已完成 PX4 SITL + QGroundControl 环境搭建，虚拟无人机可正常飞行
- C++ 只具备语法基础，Linux 能使用
- 纯仿真环境，无飞控硬件、无真机

### 1.2 目标

将 Agent 开发能力与无人机系统开发结合，走「无人机智能体应用 + 系统集成」路线。目标能力层级为：

**应用层开发为主 + PX4 系统层开发能力**。

不包含：纯算法研究（VLM/VLA 训练微调、SLAM、强化学习、控制律设计）、EKF/控制器内部算法推导、硬件设计。

### 1.3 关键优势

- 交叉稀缺：懂无人机的人多数不懂 Agent，会 Agent 的人多数不懂无人机
- 地理优势：成都是无人机重镇，中航（成都）无人机、纵横、腾盾、鲲鹏等均在本地
- 时间优势：距 2028 届秋招约一年，当前到 2027 年春是可高强度投入的窗口
- 时间预算：每周稳定 15 小时以上，论文优先，关键周可暂停

## 2. 终点能力模型

15 个月后（约 2028 年初），应具备以下可验证能力：

1. **系统级任务开发**：能从业务任务出发，独立实现「自然语言/任务指令 → Agent 分解 → MAVSDK/MAVLink → PX4 执行 → 遥测回传 → 展示」的完整链路。
2. **PX4 系统层改造**：能读懂并修改 PX4 C++ 模块（uORB、参数系统、commander/navigator、mavlink 模块），能新增自定义 MAVLink 消息/命令并端到端打通。
3. **系统认知与排障**：能讲清飞控—链路—地面站—机载—云的分工与消息流，能定位常见故障（链路断开、模式切换失败、任务不执行、失效保护触发）。
4. **可展示成果**：作品线共 4 个项目，其中 2–3 个精心打磨的公开展示（Capstone 为核心）+ 开源 PR + 竞赛/实习经历，支撑 2027 年秋招。

## 4. 路线选择

选定：**阶梯式纵深**。

| 方案 | 描述 | 取舍 |
|---|---|---|
| **阶梯式纵深（选定）** | 先应用层闭环出作品，再攻 PX4 系统层，最后做交叉点 Capstone | 快速正反馈、求职节奏对齐；系统能力约 6 个月后显性化 |
| 双线并行 | 应用层 60% + 系统层 40% 同步推进 | 更早接触系统层，但精力被切分，两边易半吊子 |
| 系统层优先 | 先补 C++/Linux 与 PX4 源码，再回到应用层 | 基础最扎实，但数月无可展示成果，求职风险高 |

## 5. 阶段设计

### 5.1 阶段 1：应用层闭环（2026-11 ~ 2026-12，8 周，约 120h）

**目标**：把「会仿真」变成「会开发」，产出第一个可公开演示的 Agent 控无人机项目。

**知识模块**：A 系统全景、B 飞行与导航概念、C MAVLink 核心消息、D MAVSDK、G Agent 交叉基础、H 工程基础（Python/Git）。

**实验与里程碑**

| 周 | 实验 | 验收 |
|---|---|---|
| 1 | 环境复核；用 MAVLink Inspector 观察心跳与遥测；画出系统链路图 | 能讲清五个组成部分与消息流向 |
| 2 | 飞行概念实操：坐标系、高度体系、飞行模式、失效保护；逐字段解读遥测 | 能解释每个遥测字段的含义与来源 |
| 3–4 | MAVSDK-Python：连接、解锁、起飞、悬停、降落、模式切换、异常处理 | 一键起降脚本；断连/超时可控 |
| 5–6 | 航线任务上传与执行、任务进度监听；Offboard 概念与最小示例；返航与围栏 | 多点巡航脚本；能解释任务模式与 Offboard 区别 |
| 7 | Agent 集成：自然语言 → 结构化任务 JSON → 校验（高度/围栏/电量）→ MAVSDK 工具执行 | 「绕方形飞一圈后降落」可自动完成 |
| 8 | 健壮性、日志、双语 README、演示视频、开源发布 | 干净环境可复现；5 分钟讲解通过 |

**作品**：Agent 控无人机 Demo（开源）。

**出口验收**：Demo 可运行；能讲清 MAVLink 心跳与命令流程、坐标转换、为什么 LLM 不能直接输出控制量；代码 review 通过。

### 5.2 阶段 2：应用层纵深（2027-01 ~ 2027-03，12 周，约 180h）

**目标**：从「能调 API」升级为「懂协议、能做任务系统」，达到应用开发实习水平。

**知识模块**：C MAVLink 精通、D 地面站与日志、F 云链路入门、G Agent 进阶、B 概念深化。

**主要内容**

1. **MAVLink 精通**：帧结构手工解析练习；核心消息序列（心跳、命令/确认、任务上传、参数）；消息速率与超时；串口/UDP 链路；mavlink-router 与多连接路由。
2. **地面站**：QGC 架构（Qt/QML + MAVLink）研读，尝试构建并从源码运行；完成一个小功能或自定义控件；或自建最小 Web 地面站（MAVLink 桥接 + 遥测仪表盘）。
3. **任务系统项目**：巡检任务系统 —— Agent 生成巡检航线、任务下发、遥测展示、任务报告；可选 MCP Server 封装。
4. **日志与排障**：ulog 结构、Flight Review 分析；人为制造三类故障并定位（链路断开、模式切换失败、任务不执行）。
5. **云链路入门**：MQTT/WebSocket 遥测上云、时序存储、告警；机队管理概念。
6. **PX4 源码轻量预读**：提前浏览 PX4 mavlink 模块与 uORB 消息定义，为阶段 3 建立印象，不做改造。
7. **连接监督与断链处理**：监听 `connection_state`；指数退避重连；断链期间设置命令闸门、停止下发新命令；恢复后重新同步遥测与任务状态；验证 PX4 失效保护（`NAV_DLL_ACT`、`COM_DL_LOSS_T`）。目标是不重启进程也能恢复连接。

**作品**：无人机巡检任务系统（Agent + 任务下发 + 遥测仪表盘 + 报告）。

**出口验收**：能手工解码一个 MAVLink 包；能讲清任务上传完整时序；项目可演示；能诊断三类仿真故障。

### 5.3 阶段 3：PX4 系统层（2027-04 ~ 2027-08，20 周，约 300h）

**目标**：具备改飞控的差异化能力，能新增模块与自定义消息并端到端打通。

**知识模块**：E PX4 系统层、H C++/Linux/调试、C 协议实现侧、B 概念支撑。

**主要内容**

| 周 | 内容 | 验收 |
|---|---|---|
| 1–4 | Modern C++ 补强（RAII、智能指针、STL、并发基础）、CMake、gdb、Linux 调试 | 能独立编译调试中等规模 C++ 程序 |
| 5–6 | PX4 构建系统、模块注册、uORB、参数系统、调度器、commander/navigator/mavlink、logger、SITL 架构 | 能画出模块与 uORB 数据流图 |
| 7–10 | 自定义 PX4 模块：订阅/发布 uORB、定义参数、写日志、SITL 运行 | 模块稳定运行，参数可调，日志可查 |
| 11–14 | 自定义 MAVLink 消息与命令端到端：消息定义 → mavlink 模块 → uORB → 消费端（MAVSDK/QGC）；命令处理与 ACK | 端到端链路打通 |
| 15–16 | 调试与测试：gdb、ulog、SITL 集成测试、CI | 测试可自动化运行 |
| 17–20 | 系统级小改造（限定范围）：如自定义失效保护动作或任务行为，附测试 | 改造有测试、有文档、可回滚 |

**作品**：PX4 自定义指令链路（自定义消息/命令 + 模块 + 消费端）。

**出口验收**：能从 MAVLink 命令追踪到模块执行；能解释 uORB 调度与消息流；代码有测试；5 分钟讲解通过。

### 5.4 阶段 4：交叉点攻坚与求职转化（2027-07 起，与阶段 3 尾部重叠；有效投入约 20 周，至 2028-01）

**目标**：把应用层与系统层合成稀缺能力，形成秋招核心竞争力。

**主要内容**

1. **Capstone v1（2027-09 前完成）**：自然语言任务 → Agent 任务规划与安全校验 → 自定义 MAVLink 命令 → PX4 机载模块执行 → 遥测/日志回传 → 故障 RAG 问答；仿真场景验证。
2. **开源贡献**：向 PX4 / QGC / MAVSDK 提 2–3 个有质量的 PR（文档、测试、小功能）。
3. **竞赛**：中国研究生未来飞行器创新大赛，用 Capstone 参赛。
4. **秋招**：2027 年 9–10 月投递成都阵营；作品集、简历、模拟面试。
5. **可选深化**：多机协同（MAVLink 路由/多机编排）、RAG 知识库、低成本硬件验证。

**Capstone v2（2028-01 前）**：补齐测试、文档、演示与可复现实验；沉淀为论文/竞赛/面试共用材料。

**出口验收**：Capstone 可演示、可讲清架构与安全边界；开源 PR 有实质进展；简历主线清晰；面试能讲透 2–3 个系统级问题。

## 8. 验证机制

1. **三级标准**：每个知识模块必须通过会用 → 能讲清 → 能改三关，缺一不算完成。
2. **阶段出口**：可运行 Demo + 5 分钟讲解 + 自测题问答（我出题、追问）。
3. **外部验证**：开源 PR 合并、竞赛结果、实习反馈、GitHub issue 互动。
4. **安全底线**：所有飞行行为先在 SITL 验证；LLM 输出必须经过确定性校验；命令白名单、围栏、双重确认。
5. **每周复盘**：做了什么、卡在哪、下周目标；写入 `notes/`。
